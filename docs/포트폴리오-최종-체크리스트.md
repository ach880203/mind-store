# 포트폴리오 최종 체크리스트

작성일: 2026-03-26

## 변경 목표

- 제출 직전 기준으로 프로젝트, 문서, 발표 준비 상태를 빠르게 점검할 수 있게 한다.

## 핵심 변경 요약

- 기능, 문서, 발표 자료를 각각 따로 보지 않고 한 번에 점검할 수 있도록 정리했다.
- "지금 남아 있어도 괜찮은 한계"와 "남아 있으면 위험한 문제"를 구분해서 보는 것이 핵심이다.

## 기능 체크

- 관리자 계정이 아닌 경우 `/admin` 접근이 막히는가
- 홈에서 일기 작성 시 현재 로그인 사용자 기준으로 저장되는가
- 로그인 빈 입력 검증이 동작하는가
- 회원가입 이메일/전화번호 검증이 동작하는가
- 상품 주문 후 재고가 줄어드는가
- 같은 상담 시간대 중복 예약이 막히는가
- 마이페이지에서 예약/주문/일기 내역이 정상적으로 보이는가
- 미완성처럼 보이는 빈 페이지가 없는가

## 화면 체크

- 한글 깨짐이 없는가
- 메인 화면 첫인상이 안정적인가
- 빈 상태 화면 문구가 자연스러운가
- 버튼 문구가 통일되어 있는가
- 상태값이 너무 제각각이지 않은가

## 문서 체크

- README가 현재 프로젝트 상태와 맞는가
- 트러블슈팅 문서에 원인-과정-결과가 들어 있는가
- 수정 전/수정 후 코드 예시가 들어 있는가
- 면접 발표 문서와 README 내용이 서로 충돌하지 않는가

## 발표 체크

- 1분 소개를 막힘 없이 말할 수 있는가
- 3분 설명에서 사용자 흐름과 핵심 기능을 빠뜨리지 않는가
- "왜 만들었는지", "무엇이 아쉬운지", "실서비스라면 어떻게 확장할지"를 말할 수 있는가
- 첫 프로젝트라는 점을 약점이 아니라 성장 포인트로 설명할 수 있는가

## 지금 남아 있어도 괜찮은 한계

- localStorage 기반 데이터 저장
- 실제 결제 기능 없음
- 서버 기반 인증 없음
- 실제 백엔드/DB 없음

## 지금 남아 있으면 위험한 문제

- 관리자 화면 무방비 접근
- 한글 깨짐
- 테스트 실패
- 데이터 저장 하드코딩
- 미완성 화면 방치

## 제출 직전 10분 점검표

1. `npm test -- --watchAll=false` 실행
2. `npm run build` 실행
3. 메인 화면 문구 확인
4. 마이페이지 데이터 확인
5. 관리자 접근 보호 확인
6. README, 트러블슈팅, 발표 문서 열어보기
