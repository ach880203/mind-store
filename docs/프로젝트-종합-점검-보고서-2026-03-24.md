# 프로젝트 종합 점검 보고서

작성일: 2026-03-24

## 1) 변경 목표

- 현재 프로젝트를 실행 가능한 범위에서 직접 확인하고, 화면/기능/구조/운영 적합성을 종합 평가한다.
- 운영 전 반드시 고쳐야 할 문제와, 이후 완성도를 높일 개선 항목을 우선순위로 정리한다.
- 매우 엄격한 기준으로 서비스화 가능 점수를 산정한다.

## 2) 핵심 변경 요약

- 개발 서버 기동과 프로덕션 빌드는 성공했다.
- 자동 테스트는 실패했다.
- 화면과 기능은 데모 수준으로는 볼 수 있지만, 실제 서비스 운영 기준으로는 인증/권한/데이터 보존/보안/품질 보증 체계가 부족하다.
- 관리자 접근 통제 부재, 로컬스토리지 기반 인증/주문/예약 저장, 하드코딩된 사용자 식별자, 미완성 관리자 상세 페이지가 핵심 리스크다.
- 현 상태 점수는 100점 만점 기준 `43점`으로 평가한다.

## 3) 코드/설명

### 실행 점검 결과

- `npm run build`: 성공
- `npm start`: 개발 서버 기동 확인, `http://localhost:3000` 응답 코드 `200` 확인
- `npm test -- --watchAll=false`: 실패

### 총평

이 프로젝트는 "감정 기록 + 상담 예약 + 상품 주문 + 관리자 화면"까지 흐름을 폭넓게 잡아 둔 점은 좋다. 다만 현재 구현은 실제 서비스가 아니라 브라우저 단일 데모에 가까운 구조다. 겉으로는 많은 페이지가 보이지만, 운영 기준으로 가장 중요한 인증, 권한 보호, 서버 저장, 테스트 자동화, 데이터 정합성, 관리자 보호가 빠져 있다.

### 잘 만든 점

- 사용자 여정이 비교적 넓다. 홈, 상담, 상품, 마이페이지, 관리자, 감정 일기까지 서비스 그림을 꽤 많이 잡아 두었다.
- `mypage` 쪽은 예약/주문/일기를 한 화면에서 묶어 보여 주려는 정보 구조가 나쁘지 않다.
- 빌드가 현재 기준에서 깨지지 않고, 기본적인 라우팅 흐름은 이어져 있다.
- 상담/주문/마이페이지가 서로 데이터 연결을 시도하고 있다는 점은 방향 자체는 좋다.

### 페이지 평가

#### 홈

- 장점: 첫 화면 메시지는 목적이 명확하다.
- 단점: 대표 가치 제안이 약하고, 서비스 신뢰를 주는 정보가 부족하다.
- 평가: 감성은 있으나 설득력은 약하다.

#### 상담 예약

- 장점: 카드 선택 → 상세 → 예약 흐름은 직관적이다.
- 단점: 실제 상담 가능 시간 충돌, 중복 예약, 담당자 배정, 예약 확정 알림이 없다.
- 평가: 데모로는 괜찮지만 실제 예약 시스템으로는 부족하다.

#### 상품

- 장점: 검색, 카테고리, 상세 이동이 있다.
- 단점: 장바구니, 결제, 재고 차감, 배송주소 확인, 주문 취소 같은 핵심이 없다.
- 평가: 카탈로그 수준이다.

#### 마이페이지

- 장점: 한곳에서 이력 조회를 묶은 방향은 좋다.
- 단점: 데이터 소유권과 정합성이 저장 구조에 크게 의존한다.
- 평가: 구조는 괜찮지만 기반 데이터가 약하다.

#### 관리자

- 장점: 예약/주문/회원/상품을 나눠 관리하려는 구조는 있다.
- 단점: 접근 통제 없음, 일부 화면 미완성, 운영 도구로 쓰기엔 위험하다.
- 평가: 운영자 콘솔이 아니라 관리자 데모에 가깝다.

## 4) 확인 방법

### 직접 실행

1. `npm start`
2. 브라우저에서 `http://localhost:3000` 접속
3. 사용자 흐름 점검
   - 홈 → 일기 작성
   - 로그인/회원가입
   - 상담 예약
   - 상품 주문
   - 마이페이지 조회
   - `/admin` 직접 접근

### 품질 점검

1. `npm run build`
2. `npm test -- --watchAll=false`
3. 브라우저 개발자도구 `Application > Local Storage`에서 회원/주문/예약 데이터 저장 방식 확인

### 우선순위별 개선 제안

1. 1차 필수
   - 관리자 라우트 보호
   - 실제 백엔드 도입
   - 인증 토큰/세션 구조 도입
   - 비밀번호 평문 저장 제거
   - 하드코딩 사용자 ID 제거
   - 테스트 체계 복구

2. 2차 필수
   - 주문 시 재고 차감/복구
   - 예약 시간 중복 방지
   - 회원/주문/예약 데이터 정합성 통합
   - 관리자 상세 페이지 완성

3. 3차 고도화
   - SEO/메타/공유 문구 개선
   - 결제/취소/알림/이메일
   - 반응형 세밀화
   - 접근성 점검
